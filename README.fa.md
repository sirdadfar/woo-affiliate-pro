افزونهٔ کامل «همکاری در فروش» (افیلیت مارکتینگ) برای ووکامرس: لینک اختصاصی هر نماینده، ردیابی کلیک، محاسبهٔ پورسانت با نرخ دسته‌بندی، پنل نماینده، درخواست تسویه و مدیریت پرداخت.

🇬🇧 [English](README.md)

---

## چرا این افزونه؟

در بازار ایران، بیشتر فروشگاه‌ها همکاری در فروش را دستی با اکسل و پیام تلگرام مدیریت می‌کنند. افزونه‌های خارجی هم سه مشکل دارند: پنل فارسی ندارند، با درگاه‌های ایرانی و واحد پول ریال/تومان درست کار نمی‌کنند، و منطق پورسانتشان برای «نرخ متفاوت هر دسته‌بندی» قابل تنظیم نیست.

این افزونه دقیقاً همان سه مشکل را حل می‌کند.

## امکانات

| بخش | توضیح |
|---|---|
| **لینک معرف** | `https://shop.ir/?ref=AB12CD` با کوکی ۳۰ روزه (قابل تنظیم تا ۳۶۵ روز) |
| **آخرین کلیک برنده است** | اگر خریدار چند لینک مختلف را باز کند، لینک آخری که قبل از خرید باز شده ثبت می‌شود — همان چیزی که در بازار مرسوم است |
| **ثبت در لحظهٔ ساخت سفارش** | کد معرف روی خود سفارش ذخیره می‌شود، نه در لحظهٔ تکمیل؛ بنابراین پرداخت با تأخیر (درگاه، کارت‌به‌کارت) انتساب را خراب نمی‌کند |
| **پورسانت درصدی** | نرخ پیش‌فرض + نرخ اختصاصی هر دسته‌بندی |
| **استثناها** | حذف محصول یا دستهٔ خاص از پورسانت |
| **سقف پورسانت** | محدود کردن مبلغ پورسانت هر سفارش |
| **مبنا** | مبلغ ردیف بعد از تخفیف؛ مالیات و ارسال به‌صورت اختیاری |
| **چرخهٔ عمر** | در انتظار → تأییدشده → پرداخت‌شده / برگشت‌خورده (با حفظ سابقه) |
| **پنل نماینده** | شورت‌کد، آمار کلیک، موجودی، جدول پورسانت و فرم درخواست تسویه |
| **مدیریت تسویه** | تأیید، پرداخت با شمارهٔ پیگیری، یا رد درخواست |
| **ضد تقلب پایه** | جلوگیری از خرید نماینده از لینک خودش (با شناسهٔ کاربر و ایمیل) |
| **HPOS** | سازگار با جدول سفارش‌های جدید ووکامرس |
| **REST API** | دریافت وضعیت و ثبت درخواست تسویه از اپ موبایل |
| **دقت مالی** | همهٔ محاسبات با عدد صحیح (بدون float) انجام می‌شود |

## نصب

```bash
git clone https://github.com/sirdadfar/woo-affiliate-pro.git
cd woo-affiliate-pro
composer install --no-dev
```

پوشهٔ پروژه را در `wp-content/plugins/` بگذارید و از پیشخوان فعال کنید. اگر بدون composer نصب می‌کنید، افزونه autoloader سبک داخلی خودش را استفاده می‌کند و همچنان کار می‌کند.

**نیازمندی‌ها:** وردپرس ۶.۰+، ووکامرس ۷.۰+، PHP 7.4+

## راه‌اندازی

### ۱) دو صفحه بسازید

| صفحه | شورت‌کد | کاربرد |
|---|---|---|
| «همکاری در فروش» | `[wap_dashboard]` | پنل نماینده (آمار، لینک، تسویه) |
| «ثبت‌نام نماینده» | `[wap_join]` | فرم ثبت‌نام |

### ۲) تنظیمات

**همکاری در فروش → تنظیمات**:

- مدت اعتبار لینک معرف (پیش‌فرض ۳۰ روز)
- نرخ پیش‌فرض پورسانت (پیش‌فرض ۱۰٪)
- نرخ اختصاصی دسته‌بندی، هر خط `شناسهٔ دسته:درصد` — مثلاً `12:15`
- محصولات و دسته‌های مستثنا (با کاما)
- سقف پورسانت هر سفارش
- حداقل مبلغ تسویه
- تأیید پورسانت در «تکمیل سفارش» یا «در حال انجام»
- تأیید خودکار نمایندهٔ جدید

### ۳) نماینده چطور لینک می‌گیرد؟

بعد از ثبت‌نام، کد ۸ کاراکتری ساخته می‌شود. لینک به شکل `https://shop.ir/?ref=AB12CD` در پنل نمایش داده می‌شود. هر صفحه‌ای از سایت که با این پارامتر باز شود، کوکی را ست می‌کند و آن کد تا پایان مهلت، به خریدهای بعدی همان مرورگر نسبت داده می‌شود.

## چرخهٔ پورسانت

```
سفارش ثبت شد
      │  کد معرف از کوکی روی سفارش نوشته می‌شود
      ▼
   pending ──── سفارش لغو/مسترد شد ────► reversed
      │
      │ سفارش تکمیل شد (یا «در حال انجام» بسته به تنظیم)
      ▼
  approved ──── درخواست تسویه ثبت شد ────► payout requested
      │                                          │
      │ مدیر پرداخت کرد                          │
      ▼                                          ▼
    paid ◄──────────────────────────────────  پرداخت شد
```

نکتهٔ مهم: پورسانت هرگز حذف نمی‌شود، فقط وضعیتش عوض می‌شود. اگر سفارشی برگشت بخورد، رکورد `reversed` می‌ماند تا در گزارش ماهانه معلوم باشد چرا موجودی نماینده کم شده است.

## تست

```bash
composer install
vendor/bin/phpunit
```

```
OK (70 tests, 373 assertions)
```

چه چیزی تست شده است؟ **لایهٔ دامنه** — همان جایی که پول محاسبه می‌شود:

- دقت پولی: جمع صدبارهٔ ۰.۱ بدون خطای شناور
- درصد با گرد کردن نیم‌به‌بالا و محاسبهٔ عدد صحیح
- اولویت نرخ: استثنای محصول → استثنای دسته → نرخ دسته → نرخ پیش‌فرض
- انتخاب قطعی نرخ وقتی محصول در چند دسته است
- مالیات و ارسال فقط وقتی روشن باشند
- پورسانت ثابت فقط یک‌بار برای هر سفارش
- سقف پورسانت با سطر تعدیل، به‌طوری‌که جمع سطرها همیشه با مبلغ نهایی برابر بماند
- ماشین وضعیت: جلوگیری از پرش از «در انتظار» به «پرداخت‌شده»
- موجودی: پورسانت در انتظار قابل برداشت نیست، درخواست باز پول را رزرو می‌کند
- اعتبارسنجی کد معرف در برابر تزریق (`<script>`، `../`، کوتیشن)
- جلوگیری از خرید نماینده از لینک خودش

چه چیزی تست نشده است؟ **لایهٔ یکپارچه‌سازی با وردپرس/ووکامرس** (هوک‌ها، رندر پنل، جدول‌های ادمین) چون به نصب واقعی وردپرس و دیتابیس نیاز دارد. برای این بخش، کد را طوری نوشته‌ام که همهٔ فراخوانی‌های ووکامرس از API عمومی (`$order->get_meta()`, `wc_get_order`, `wc_get_price_decimals`) باشد و روی HPOS هم کار کند. صادقانه بگویم: قبل از استفاده روی فروشگاه واقعی، یک سفارش تستی بزنید و مسیر پورسانت را در پیشخوان ببینید.

## REST API

| مسیر | متد | دسترسی | توضیح |
|---|---|---|---|
| `/wp-json/wap/v1/me` | GET | کاربر واردشده | کد، وضعیت و موجودی نماینده |
| `/wp-json/wap/v1/payouts` | POST | کاربر واردشده | ثبت درخواست تسویه (`amount`) |
| `/wp-json/wap/v1/affiliates` | GET | `manage_woocommerce` | فهرست نمایندگان |

احراز هویت با کوکی وردپرس + nonce، یا Application Password.

## امنیت

- همهٔ کوئری‌ها با `$wpdb->prepare`
- همهٔ خروجی‌ها با `esc_html` / `esc_attr` / `esc_url`
- اکشن‌های ادمین با `nonce` + `current_user_can`
- کد معرف فقط `[A-Z0-9]` بعد از نرمال‌سازی؛ هر کاراکتر دیگری رد می‌شود
- IP بازدیدکننده به‌صورت HMAC-SHA256 ذخیره می‌شود، نه خام
- کوکی معرف `HttpOnly` و `SameSite=Lax` است
- در حذف افزونه، داده‌های مالی به‌صورت پیش‌فرض پاک **نمی‌شوند**
